# Local RAG with Python, LangChain, Ollama and FAISS

A local Retrieval-Augmented Generation (RAG) pipeline. It ingests PDF/TXT/Markdown documents, chunks them, embeds chunks with Ollama, indexes them in FAISS, retrieves relevant passages, and asks a local LLM to answer with chunk citations.

## Architecture

1. `ingest.py`: loads supported files from `data/knowledge_base`, splits text into overlapping chunks, and writes `data/processed/chunks.jsonl`.
2. `index.py`: embeds the chunks using `nomic-embed-text` and stores a FAISS index in `data/index`.
3. `retrieve_generate.py`: retrieves the top-k chunks and calls `qwen3.5:9b` with a context-only prompt.
4. `evaluate.py`: runs the JSONL evaluation set and reports source hit rate and expected-term coverage.

## Requirements

- Python 3.10+ (Python 3.11 is a safe default for broad package compatibility).
- Ollama installed and running.
- Enough RAM to run the selected local LLM.

## Setup on Windows (PowerShell)

```powershell
# 1. Create and activate a virtual environment
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1

# 2. Install dependencies
python -m pip install --upgrade pip
pip install -r requirements.txt

# 3. Pull the models
ollama pull nomic-embed-text
ollama pull qwen3.5:9b
```

If you already have Python installed, replace `py -3.11` with your installed version. If the 9B model is too slow or memory-heavy, use a smaller model available in Ollama and update `LLM_MODEL` in `retrieve_generate.py`.

## Add documents

Copy your own PDFs, `.txt`, or `.md` files into:

`data/knowledge_base/`

A small fictional sample document is included so you can test the pipeline immediately. Replace or supplement it with documents relevant to your assignment.

## Run the pipeline

Run commands from the project root, in this order:

```powershell
python ingest.py
python index.py
python retrieve_generate.py "What is retrieval-augmented generation?"
```

Interactive mode:

```powershell
python retrieve_generate.py
```

Change the number of retrieved chunks:

```powershell
python retrieve_generate.py "Your question" -k 6
```

After changing or adding documents, rerun both `ingest.py` and `index.py`.

## Evaluation

Edit `evaluation/questions.jsonl` so each line is one JSON object. Example:

```json
{"question":"What does the sample say about chunk overlap?","expected_source":"rag_basics.md","expected_terms":["overlap"]}
```

Then run:

```powershell
python evaluate.py
```

The script writes `evaluation/results.json`. `source_hit_rate_at_4` checks whether the expected source appeared in the top four retrieved passages. `expected_term_coverage` is a simple exact-term proxy, not a full semantic correctness metric. Manually inspect answers and citations and report the actual measured results; do not invent metrics.

## Citation design

Each chunk gets an ID such as `[CH0001]`. The generator is instructed to cite chunk IDs and abstain if the context is insufficient. The CLI also prints the retrieved file, page (for PDFs), distance score, and a short passage preview.

Important: citations are generated by the LLM, so they must be checked. A citation-aware prompt does not guarantee that every claim is supported. For a stronger implementation, validate cited IDs against retrieved IDs and add a reranker or human-reviewed evaluation.

## Limitations and next improvements

- Local FAISS is suitable for a single-user prototype, not a multi-user hosted service.
- The sample evaluation uses lightweight proxy metrics. Add human-labelled relevant chunks and metrics such as Recall@k / MRR for a stronger report.
- Scanned PDFs need OCR before text can be indexed.
- `allow_dangerous_deserialization=True` is used only for loading this project's own locally generated FAISS index. Do not load index files from untrusted sources.
